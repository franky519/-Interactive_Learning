# finance/learning/AGENTS.md

这里用于**系统性学习财务管理相关课题**（投资、理财、财报、估值、预算、保险等均可）。

## 强制工作流

- 每个课题一个文件夹。
- 每个课题必须有 `GOALS.md`：生成任何内容之前，先读它；如果不存在先创建再继续。
  - GOALS.md 用于对齐学习动机、预期目标、深度期望和特别关注方向，确保后续内容为用户定制。
- 每章文章按序号命名：`01_{本章学习内容}.md`、`02_...`。
- **章节与 QA 是一对原子产物，不是可选项：**
  - 写完/更新 `NN_标题.md` 的**同一次任务**里，必须同时交付 `NN_QA.md`。
  - 命名一一对应：`01_xxx.md` ↔ `01_QA.md`，`02_xxx.md` ↔ `02_QA.md`。
  - 只写正文不写 QA、或把 QA 留到"下次再补"，都视为**任务未完成**。
- 生成下一篇文章前：必须先阅读上一章 `*_QA.md` 的全部反馈；只有掌握度约 80–90% 才推进。

## QA 文件结构（模板）

```markdown
# NN QA — {本章标题}

## 检验问题
**Q1.** ...
**Q2.** ...
**Q3.** ...

## 延伸思考
**T1.** ...
**T2.** ...

> 在下方写下你的回答、疑问、或感兴趣的方向。
```

- **检验问题**：3 题左右，紧扣本章核心概念，能暴露是否真懂（最好带场景/判断，而不是纯背定义）。
- **延伸思考**：1–2 题，把概念接到用户自己的生活、工作或已有经验上。
- 用户作答区放在文件后半；后续反馈/纠正也写回同一文件。

## QA 交互机制

用户阅读文章后，会在 QA 文件中写下对问题的回答、感悟、反馈。

只有检验用户的回答、感悟、反馈没有问题之后才生成下一篇文章。如果有问题，在 QA 里纠正。

生成下一篇文章时，必须先阅读用户在前一篇 QA 中的所有反馈，基于用户的理解程度和兴趣方向来调整内容深度和方向。

这样形成一个自适应的学习梯度，确保内容既不过于简单也不过于跳跃。

## 写作风格

清晰、有深度、避免空洞的教科书腔调，像一个懂行的朋友在讲解。
